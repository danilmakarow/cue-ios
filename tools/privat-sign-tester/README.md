# Privat Sign Tester

Крихітний **локальний** інструмент, щоб протестувати підпис договору кваліфікованим
електронним підписом (КЕП) ПриватБанку. Zero-dependency: лише вбудовані модулі Node.js,
`npm install` не потрібен.

> **Головне:** підпис виконується **клієнтськи, у твоєму браузері** через віджет ІІТ EU Sign.
> Ключ і пароль **не покидають браузер** і не йдуть ні на цей сервер, ні до ІІТ у відкритому вигляді.
> Локальний Node-сервер лише віддає сторінку і тримає ендпоінт `/callback`.

## Що вміє

Два режими (перемикач у формі):

1. **Файловий ключ — працює зараз.** Завантажуєш договір (будь-який файл) + читаєш свій
   файловий ключ ПриватБанку (`.dat` / `.jks` / `.pfx` + пароль) через захищену форму
   віджета ІІТ → отримуєш **CAdES `.p7s`** (attached або detached, опційно з позначкою часу).
   Це реальний підпис.

2. **SmartID (QR / Приват24) — скелет.** Демонструє потік «сервер → QR → очікування
   callback». **Підпис тут мок**, не справжній `.p7s`: справжній SmartID через Приват24
   вимагає **партнерського API ПриватБанку** (креди + зареєстрований callback-URL), якого
   в цьому тесті немає. Скелет готовий: щойно з'являться креди, підключаєш реальні виклики
   замість `/api/mock-smartid-sign`.

## Вимоги

- **Node.js 18+** (перевірено на 22).
- Реальний **файловий ключ ПриватБанку** для режиму 1 (експортуєш у Приват24 → «Бізнес» →
  ЕЦП, або на `acsk.privatbank.ua`).
- Браузер із доступом до `eu.iit.com.ua` (звідти вантажиться SDK підпису — з української
  мережі працює; у деяких хмарних середовищах домен заблоковано).
- **ngrok** — лише якщо тестуєш callback ззовні (режим 2 або надсилання підпису на публічний URL).

## Запуск

```bash
cd tools/privat-sign-tester
node server.js              # → http://localhost:3000
# порт змінюється через PORT=8080 node server.js
```

Відкрий `http://localhost:3000` у браузері.

### З ngrok (для публічного callback)

В окремому терміналі **на своїй машині**:

```bash
ngrok config add-authtoken <ТВІЙ_ТОКЕН>   # один раз
ngrok http 3000
```

Візьми з виводу ngrok публічний `https://xxxx.ngrok-free.app`, додай `/callback`
і встав у поле «Callback URL» у формі. Сервер сам спробує підняти ngrok, якщо бінарник
є в `PATH` (вимкнути: `START_NGROK=0 node server.js`).

## Флоу (як воно працює)

### Режим 1 — файловий ключ (реальний підпис)

```
Браузер                          Віджет ІІТ (iframe)            Локальний сервер
  │  1. обираєш договір (файл)                                       │
  │  2. «Зчитати ключ» ──────────▶ форма: файл ключа + пароль        │
  │                               (ключ/пароль лишаються тут)        │
  │  3. «Підписати» ────────────▶ SignData(договір) → .p7s (base64)  │
  │  4. ⬇︎ завантаження contract.ext.p7s                             │
  │  5. (опц.) POST підпис ─────────────────────────────────────────▶ /callback (лог)
```

- Крок 3 рахує геш договору (ДСТУ 7564 «Купина»), підписує алгоритмом ДСТУ 4145 приватним
  ключем і пакує у CAdES/CMS → `.p7s`.
- **attached** → договір усередині `.p7s` (один файл). **detached** → окремий `.p7s`
  (зберігай разом з оригіналом; для перевірки потрібні обидва).
- Перевірити результат: `czo.gov.ua/verify` або `ca.diia.gov.ua/verify`.

### Режим 2 — SmartID cloud (скелет)

```
Браузер                 Локальний сервер            [ реальний ПриватБанк — потрібне API ]
  │  «Створити сесію» ──▶ /api/mock-smartid-sign            (у реалі: створення сесії підпису)
  │  показує QR                                              (у реалі: QR від ПриватБанку)
  │  сканування в Приват24 ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─ ─▶ підтвердження підпису
  │                          /callback ◀── ─ ─ ─ ─ ─ ─ ─ ─ ─ ПриватБанк шле результат
  │  опитує /api/last-callback ─▶ показує отриманий підпис
```

У скелеті замість ПриватБанку сервер сам за 2 секунди кладе **мок-підпис** у
`lastCallback`, щоб було видно, як замикається цикл через `/callback` + ngrok.

## Відомі місця для підправлення

- **Версія віджета ІІТ.** У формі поле «Віджет ІІТ EU Sign (URI)» містить версію
  (напр. `v20240301`). Якщо ключ не читається — онови на актуальну з
  `eu.iit.com.ua/sign-widget/`.
- **Назви методів SDK.** Точні сигнатури `ReadPrivateKey` / `SignData` можуть відрізнятися
  між версіями віджета. У `app.js` такі місця позначені коментарем `// ADJUST`.
- **SmartID реальний.** Заміни `/api/mock-smartid-sign` і мок у `server.js` на виклики
  партнерського API ПриватБанку, коли отримаєш доступ.

> Це тестовий інструмент, не частина iOS-застосунку. Можна видалити папку без наслідків.
